# 迭代归档（iteration-archive）

将本项目的功能新增/修改自动归档到 `docs/功能演进时间线.md`。核心要求：**自动判断变更归属的功能模块**，按文档既有格式追加条目，并同步版本信息。

## 触发时机

1. **自动触发**：当本次会话任务属于「新增功能 / 修改功能 / 重构影响行为」，在代码改动完成并验证后，归档是任务完成的最后一步（Definition of Done），必须执行，无需用户提醒。
2. **手动触发**：用户说「归档」「记录迭代」「更新时间线」。此时若会话内无代码变更，读取 `git log` 最新提交作为归档对象。
3. **跳过**：纯文档改动、问答解释、临时调试的 typo 修复。拿不准是否值得归档时，问用户一句。

## 归档流程

1. **收集证据**：会话内有改动 → 读 `git diff`（未提交）或 `git log -p -1`（已提交）；同时回顾用户的需求描述，明确「变更意图」。
2. **读取文档现状**：读 `docs/功能演进时间线.md`，获取当前的模块章节列表（权威来源）、最新版本号、候选池。
3. **判定归属模块**：按下方「模块归属判定规则」执行。
4. **确定版本号**：
   - 用户可感知的新能力 → minor +1（如 v0.1 → v0.2）；
   - 修复 / 小调整 / 行为不变的重构 → 版本不变，条目只记日期。
5. **写入文档**：
   - 在归属模块的条目列表末尾追加：`- **[vX.Y YYYY-MM-DD]** 条目内容`（日期用当天，X.Y 为归档后版本）；
   - 若本次兑现了该模块的某条「演进方向」：删除该 `- [ ]` 行，并在新条目中注明「已兑现：xxx」；
   - minor 版本变化时，在「版本总览」表加一行（commit 未产生时填 `待提交`，并提醒用户提交后可补 hash）；
   - 涉及候选池的：已兑现候选移出表格；产生新待办则按格式加入并给优先级。
6. **输出归档摘要**：告知用户写入了哪个模块、哪些条目、版本是否变化，附文档路径。

## 模块归属判定规则

按优先级依次执行：

### 第 1 步：按变更意图判断，文件路径只作辅助

同一文件可能对应多个模块（如 `agent.js` 横跨主循环 / 防死循环 / Token 统计），**禁止**仅凭「改了哪个文件」定模块。先问：这次变更解决了什么问题、改变了什么行为？

### 第 2 步：信号 → 模块映射表

| 变更信号（意图或代码特征） | 归属模块 |
|---|---|
| while 循环主体、消息组装、Observation 回填、Final Answer、多工具执行方式 | ReAct 主循环 |
| 终止条件、maxIterations、空输出兜底、重复 Action 检测 | 防死循环兜底 |
| stream/SSE、delta 分片、tool_calls 累积拼接、onDelta、[DONE]/usage 帧解析 | 真·流式输出 |
| tools/toolImpl、新增或修改工具、工具参数 schema、calculator/get_weather/get_luck | Function Calling 工具体系 |
| usage 统计、include_usage、x-* 响应头兜底、计时汇总展示 | 用时与 Token 统计 |
| AbortController、stop 按钮、signal 透传、中断行为 | 手动停止 |
| vite proxy、CORS、.env、API Key、部署/后端转发 | 工程配套（CORS 代理与 Key 管理） |
| JSX、渲染、着色、setState/flat、光标、UI 交互 | 控制台 UI |

> 模块名以文档当前章节标题为准（上表为其快照）；若文档后续增删了模块，以文档为准。

### 第 3 步：多模块与边界情况

- **跨模块变更** → 拆成多条目，分别写入各自模块；每条聚焦该模块视角的变更点。
- **主变更 + 顺带小改**（如改工具时顺手改了个日志颜色）→ 只记主模块，顺带改动一句话并入同一条目，不单独开条。
- **全新类型的功能**，不属于任何现有模块 → 在文档末尾新增章节 `## N. <模块名>`（N 顺延），并把它加入映射表的认知中（下次归档直接命中）。
- **仍无法判断** → 向用户列出 1-2 个候选模块并简述理由，由用户选择；禁止默默猜一个。

## 条目写作规范

- 语言：中文，风格与文档现有条目一致（客观、精炼、一个要点一条）。
- 必须具体：写行为/接口/文件的实质变化，禁止「优化了代码」「完善了功能」这类空话。
- 涉及取舍时写出「选择了 X 而非 Y，因为 Z」。
- 一次任务在该模块通常产生 1-3 条条目，不逐 commit 罗列。

## 完成检查清单

- [ ] 归属模块判定基于变更意图，而非仅文件路径
- [ ] 条目格式与文档现有条目一致（粗体版本+日期）
- [ ] 已兑现的「演进方向」行已处理
- [ ] 版本总览表与版本号规则一致
- [ ] 候选池已同步
- [ ] 已向用户输出归档摘要
