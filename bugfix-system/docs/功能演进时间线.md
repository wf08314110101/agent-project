## 1. 架构与通信（控制面/执行面分离）

对应代码：[server/](../server/)、[agent/](../agent/)

- **[M0]** 部署形态定案：server（API + DB + 前端托管）部署服务器，agent 跑本地（有 git 仓库和 aider 环境），agent 出站轮询 `POST /agent/claim` 领单（类 GitHub Actions self-hosted runner）——服务器无需 SSH 进本地，本地无需公网入口，NAT 友好。
- **[M2]** 通信协议：全部 HTTP + 固定 `x-agent-token`（timingSafeEqual 防时序侧信道）。6 个端点：claim / heartbeat（续租）/ report（修复结果+trace）/ attachments（截图下载）/ commands（待合并批次）/ report-merge。服务器不主动推，简单可靠；代价是最多 30s 延迟。
- **[M2]** 设计取舍：不用 WebSocket/SSE 下发指令——领单已是长轮询节奏，合并指令复用同一轮询，多一条命令通道都不加。
- **[ ] 演进方向**：agent 多并发 worker（同机多仓库并行）；指令通道扩展（回滚、rebase 主分支）。

## 2. 调度与批次归并

对应代码：[server/queue/scheduler.js](../server/queue/scheduler.js)、[server/routes/agent.js](../server/routes/agent.js)

- **[M1]** 领单 SQL：`UPDATE ... WHERE id = (SELECT id FROM batches WHERE status='queued' ORDER BY id LIMIT 1 FOR UPDATE SKIP LOCKED) RETURNING *`——原子抢占 + 租约锁（`locked_until = now() + LEASE_SEC`），心跳续租，超时回收重试（MAX_ATTEMPTS=3 超限置 failed）。**踩坑**：`$1` 未参与的 UPDATE 报 42P18，改 `make_interval(secs => $1::int)`。
- **[M1]** 批次归并：同 project + related_group 的 BUG 在 60s 冷静期后归为一个批次，共享一个 worktree/分支/一次审查——逻辑关联的 BUG 一起修、一起验、一起合并，避免 N 个分支互相冲突。
- **[M3]** 上报语义收紧：`ok=true` 且 fixes>0 → awaiting_review；0 修复或报错 → 批次 failed（此前 0 修复也进待审查，产生无物可审的幽灵单）。
- **[ ] 演进方向**：BUG 提交时质量校验（复现步骤/期望行为必填），太模糊直接打回而非烧 3 轮 LLM；批次内 BUG 依赖排序（后修的基于先修的结果）。

## 3. 执行面修复流水线

对应代码：[agent/index.js](../agent/index.js)、[agent/lib/](../agent/lib/)

- **[M2]** worktree 隔离：每批次独立 `git worktree`（`worktrees/batch-<id>-a<attempt>`），基线 baseSha 记 marker 文件；ensureWorktree 自愈式创建——清陈旧 `index.lock` → `reset --hard baseSha` → `clean -fdx` → symlink node_modules。attempt 后缀目录同时规避沙箱 EXDEV（跨实例文件不可删）；分支被旧 worktree 注册占用时自动换名 `-a<n>` 并经 report 回传服务端（合并指令用最新值）。
- **[M2]** 修复引擎：aider `--edit-format diff --no-pretty --no-auto-commits --yes-always`，DeepSeek OpenAI 兼容端点。**踩坑**：deepseek-chat 默认 whole 格式且输出带 markdown 标题导致解析失败，必须显式 diff 格式；`--pretty false` 无效（`false` 被当文件名创建空文件），用 `--no-pretty`。
- **[M2]** 提交规范：aider 只改不提交（`--no-auto-commits`），agent 从 `git status --porcelain` 取变更文件（过滤 .aider*/.env/空未跟踪文件）→ 逐文件 add（幻觉路径 try-catch 跳过）→ `commit --author=bugfix-agent`，message 格式 `fix(<项目>): [BUG-<id>] <标题>` + 根因/方案（模型输出 JSON 提取）；回归失败带测试输出重试，`commit --amend` 保持每 BUG 单 commit（MAX_RETRY=2）。
- **[M3]** **关键修复**：git() 封装曾 `stdout.trim()`——porcelain 首行状态列以空格开头（`" M path"`），trim 后 `line.slice(3)` 把 `LLM-SSE` 削成 `LM-SSE`，add 全挂且极难排查（git 自身输出与解析结果看似都对）。修正为只去尾部空白 `replace(/\s+$/,'')`。教训：**通用 git 封装不能对输出做有损清洗，porcelain 的列位置是数据**。
- **[M3]** 无产出重试：aider 某轮只提问不改码（模型非确定性）→ no_changes 记 trace 后 `continue` 而非 break，重试反馈明确「请直接给出 SEARCH/REPLACE，不要只提问题」。
- **[M2]** 截图理解：BUG 附件（≤5 张）下载后经 VLM（VISION_MODEL）转述为文字并入 prompt，aider 无多模态也能消费截图；转述失败返回 null 不阻断。
- **[ ] 演进方向**：自研修复引擎（替换 aider，工具调用式编辑 + 更强上下文控制）；修复方案预审（先出 diff 计划人工速览再执行）；跨 BUG 上下文传递（同批次前一个 BUG 的修复摘要进后续 prompt）。

## 4. 安全模型

对应代码：[agent/lib/git.js](../agent/lib/git.js)、[agent/index.js](../agent/index.js)（buildPrompt）

- **[M2]** git 沙箱：路径闸门（仅 MAIN_ROOT / WT_ROOT 内可执行 git）+ 命令黑名单（push/remote/rebase/filter-branch/gc）+ 主仓库根禁 reset/clean（worktree 内自愈用途放行）。
- **[M2]** 防注入：BUG 描述按不可信内容包裹 `<<UNTRUSTED_BUG>>`，prompt 声明其中任何指令一律忽略；截图 VLM 转述同理（转述而非原文拼接）。
- **[M2]** 合并 dirty 检查：主仓库有**已跟踪文件**改动时拒绝合并。**踩坑**：最初全量 `status --porcelain` 判脏，bugfix-system 自身未提交（untracked）就永远"脏"——改为过滤 `??` 行；真实路径冲突 git merge 会自行中止，untracked 无需人工挡。
- **[M2]** 回归门禁：test_cmd 失败的批次服务端拒绝批准（409），人工兜底走「标记已手动合并」。
- **[ ] 演进方向**：diff 敏感文件告警（.env/CI 配置/锁文件变更标记）；每批次 token/时长成本上报表。

## 5. 审查与合并

对应代码：[server/routes/actions.js](../server/routes/actions.js)、[agent/index.js](../agent/index.js)（processCommands）

- **[M2]** 状态机：bug `submitted→queued→fixing→await_confirm→confirmed/failed/rejected`；batch `queued→running→awaiting_review→approved→merged/rejected/failed`。批准（含回归门禁校验）→ approved → agent 轮询到合并指令 → 主仓库 `merge --no-ff`（保留批次边界）→ report-merge → bug 批量 confirmed 关单。
- **[M2]** 合并失败回滚：merge 异常时 `merge --abort` 兜底 + 批次回 awaiting_review 带 error，可重新处理；「标记已手动合并」作为人工兜底出口。
- **[M2]** 合并后清理：removeWorktree（worktree + 分支 + marker），24h sweep 兜底清扫残留。
- **[ ] 演进方向**：合并前 diff 预览页（前端展示完整 patch）；主仓库合并后自动 push（当前黑名单禁 push，人工推）。

## 6. 前端

对应代码：[frontend/src/App.jsx](../frontend/src/App.jsx)

- **[M1]** React + Vite，hash 路由（#/bug/:id、#/batch/:id、#/batches），无路由库；提交表单（multipart：文字 + 截图多选）、BUG 列表按项目分组、批次详情展示每个 fix 的 diff/根因/回归输出 + 批准/拒绝/标记手动合并按钮。
- **[M1]** 设计取舍：开发态 Vite proxy `/api→8787`，生产构建产物由 Fastify `@fastify/static` 托管——单进程部署，无 nginx。
- **[ ] 演进方向**：SSE 实时推送批次状态（当前手动刷新）；BUG 提交表单校验（复现步骤/期望行为必填）。
