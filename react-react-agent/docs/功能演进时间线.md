## 1. ReAct 主循环

对应代码：[src/agent.js](../src/agent.js)

- **[v0.1]** 实现 `while(true)` 主循环：每轮 = 流式问模型 → 有 `tool_calls` 则执行工具、回填 Observation → `continue`；无则输出 Final Answer 结束。
- **[v0.1]** 设计取舍：循环逻辑与 UI 完全解耦，`agent()` 只通过 `onToken` / `onLog` 回调输出，可脱离 React 单独运行。
- **[v0.1]** 设计取舍：Observation 回填 `{ role: 'tool', tool_call_id }` 与请求配对——这是 OpenAI Function Calling 规范的硬性要求，漏掉会导致下一轮请求 400。
- **[v0.1]** 设计取舍：多个工具调用按 `for` 串行执行，简单可靠；并行执行留作演进。
- **[v0.3 2026-09-11]** 重构 `agent()` 签名：`userPrompt` → `messages` 共享数组，移除内置 user prompt 创建；会话上下文由调用方持有、跨多次调用累积（多轮记忆移出循环层）。顺带在 llm.js 新增 `maxTokens`（默认 2048）注入请求体 `max_tokens`，限制单轮输出长度。
- **[ ] 演进方向**：多工具并行执行（`Promise.all`）；Thought 阶段结构化展示。

## 2. 真·流式输出

对应代码：[src/llm.js](../src/llm.js)

- **[v0.1]** 请求体 `stream: true`，用 `res.body` 的 `ReadableStream` 逐行解析 SSE `data:` 帧，正文 `content` 逐 token 回调 UI。
- **[v0.1]** 设计取舍：`tool_calls` 的 `name` / `arguments` 跨 chunk 分片，以 `index` 为 key 累积拼接；用 `started` 标记保证「调用工具」前缀只打印一次，工具名本身逐字流式显示。
- **[v0.1]** 设计取舍：工具参数 JSON 分片不合法、不可逐字渲染，故完整累积后由 agent 层一次性补打——牺牲参数的逐字感换取正确性。
- **[v0.1]** 细节处理：`[DONE]` 帧提前返回；usage 帧（`choices` 为空）先读取再 `continue`。
- **[ ] 演进方向**：参数 JSON 的增量语法高亮渲染。

## 3. Function Calling 工具体系

对应代码：[src/tools.js](../src/tools.js)

- **[v0.1]** 建立「定义 + 实现」双表结构：`tools` 数组（给模型看的 JSON Schema）与 `toolImpl` 对象（实际执行函数）同名映射，新增工具只需各加一条。
- **[v0.1]** `calculator`：正则白名单 `^[\d+\-*/ ().]+$` + `Function` 构造器求值，替代裸 `eval`（风险更低）；加 `isFinite` 校验与两位小数取整。
- **[v0.1]** `get_weather`：模拟返回值，仅演示 Action 分发链路。
- **[v0.1]** `get_luck`：接入真实免费 API（celesian.com，免 key 允许跨域），中文星座 → 英文签名映射，未知星座报错并列出可用值。
- **[v0.4 2026-09-11]** `get_weather` 接真实 API（已兑现「get_weather 接真实 API」，commit `4ba7003`）：Open-Meteo 双跳——geocoding 城市名→经纬度，forecast 取当前温度/湿度/WMO 天气码/风速，天气码映射中文描述；免 key 且允许跨域，替换原模拟返回。
- **[v0.4 2026-09-11]** 参数校验收口 agent 层：执行工具前按 `tools` 里已声明的 JSON Schema 统一校验（`utils.js` 新增 `validateArgs`，查必填 + 基础类型）；失败不调工具，转「参数校验失败: …」Observation 回喂模型自我修正（Langfuse Span 标 WARNING）。选择复用 schema 统一校验而非各工具内零散校验，因为 LLM 幻觉畸形参数时可快速失败，且报错文案对模型可读。
- **[v0.4 2026-09-11]** 网络型工具有限重试：`tools.js` 导出 `networkTools` 标记（get_weather/get_luck）；agent 层仅对瞬时错误（fetch 连接失败 / HTTP 5xx / 429，`isRetryable` 判定）最多重试 2 次、指数退避 500ms/1s，重试次数经 Span metadata（`attempt`/`attempts`）记入 Langfuse。不做通用重试：参数/业务类错误重试必然再失败，且与 ReAct 的「错误 Observation 回喂模型自愈」机制重叠。
- **[ ] 演进方向**：工具级超时控制；工具执行结果缓存。

## 4. 防死循环兜底

对应代码：[src/agent.js](../src/agent.js#L31-L41)

- **[v0.1]** 双终止条件：① `step >= maxIterations`（默认 6，调用方可覆盖）强制停止；② 无 `tool_calls` 且正文为空时同样兜底停止，避免空转。
- **[v0.1]** 设计取舍：达到上限按 `warn` 处理而非抛错，仍正常输出用时/Token 汇总——兜底是「体面退出」而不是失败。
- **[ ] 演进方向**：重复 Action 检测（连续 N 轮相同工具 + 相同参数时提前终止，比纯次数上限更聪明）。

## 5. 用时与 Token 统计

对应代码：[src/agent.js](../src/agent.js#L18-L28)、[src/llm.js](../src/llm.js#L36-L41)

- **[v0.1]** `startedAt` 记录起点，每轮累加 `assistantMsg.usage`，结束时统一输出 `总用时 + Token(输入/输出)`，UI 以紫色 meta 样式区分。
- **[v0.1]** 设计取舍：Token 读取双通道——首选 `stream_options: { include_usage: true }` 从 SSE 主体 usage 帧读取（标准做法）；provider 不支持时回退响应头 `x-prompt-tokens` 等。选主体优先是因为代理常吞掉自定义 `x-*` 头。
- **[ ] 演进方向**：按轮次细分耗时与 Token 分布，定位「哪一轮最烧钱」。

## 6. 手动停止

对应代码：[src/AgentConsole.jsx](../src/AgentConsole.jsx#L25-L46)

- **[v0.1]** UI 层创建 `AbortController` 存入 `ref`，`signal` 一路透传到 `fetch`；点停止即中断当前请求。
- **[v0.1]** 设计取舍：`AbortError` 单独识别为「⏹️ 已手动停止」而非错误，与真实异常（红色）区分。
- **[ ] 演进方向**：停止时保留已生成的半截输出并标注中断位置。

## 8. 控制台 UI

对应代码：[src/AgentConsole.jsx](../src/AgentConsole.jsx)

- **[v0.1]** 渲染模型：`flat` 数组存 `{ ch, type }` 单字符，token 到达即 `setState` 追加；一次性日志（`onLog`）也拆成单字入列，统一渲染路径只有一种。
- **[v0.1]** 按阶段着色区分语义：正文白 / 工具青 / 动作黄 / 观测绿 / 警告橙 / 错误红 / 轮次灰 / 汇总紫，运行中带闪烁光标。
- **[v0.1]** 性能取舍：每 token 一次 `setState`，长输出下重渲染频繁会变卡——教学项目可接受。
- **[v0.3 2026-09-11]** 重写 AgentConsole 适配多轮会话：`useReducer` 管理展示状态（append 动作不可变更新，避免闭包过期）；`sessionRef` 持有发给 LLM 的完整会话上下文，UI 按 user/assistant 分块渲染多轮对话；新增滚动容器 rAF 跟随自动滚底。
- **[ ] 演进方向**：`requestAnimationFrame` 批量 flush token，降低重渲染次数。

## 9. 可观测性（Langfuse Trace 链路）

对应代码：[src/langfuse.js](../src/langfuse.js)、[src/agent.js](../src/agent.js) 的埋点

- **[v0.2 2026-09-10]** 接入官方 `langfuse` SDK：选择 SDK 而非手写 ingestion 客户端，因为本项目无零依赖约束，SDK 自带批量上报、重试与格式兼容；新增 `src/langfuse.js` 单例封装。
- **[v0.2 2026-09-10]** Trace 结构设计：一次 `agent()` 运行 = 一条 Trace（input=用户问题，结束 update 写入 Final Answer 与用时/Token 汇总）；每轮 LLM 调用 = Generation（input=完整上下文、output=正文+tool_calls、usage 来自 include_usage 帧）；每次工具执行 = Span（input=参数、output=Observation，出错标 ERROR 级）。埋点只放编排层，llm.js / tools.js 零改动。
- **[v0.2 2026-09-10]** 非侵入设计：未配置 `VITE_LANGFUSE_*` 时 SDK 替换为全空转 stub，agent.js 零分支；手动停止 / 迭代上限 / API 异常路径也会收口 Trace（WARNING / ERROR 级），Langfuse 里能看到中断的运行。
- **[ ] 演进方向**：后端代理上报（Secret Key 不进前端产物）；控制台展示 Trace 页面直链。

## 10. Token 预算管理（止损与降级）

对应代码：[src/budget.js](../src/budget.js)、[src/agent.js](../src/agent.js) 的预算检查点

- **[v0.5 2026-09-11]** 新增 `src/budget.js` 预算管理：分层预算——单轮软限 `perTurnTokens`(12000)、会话总硬限 `totalTokens`(60000)、降级阈值 `degradeAt`(0.8)；token 用「字数/1.3」粗估（中文≈1字/token、英文≈4字符/token 的折中），真实消耗以每轮 API 返回的 usage 记账。
- **[v0.5 2026-09-11]** 双检查点嵌入主循环：每轮调用前 `check` 预估——预计超总预算直接止损退出（warn + finish）；超单轮软限则降级裁剪历史至最近 8 条消息；累计用量近阈值则切换小模型（`llm.js` 的 `callLLMStream` 新增 `o.model` 覆盖参数）。每轮调用后再以真实 usage 复检，防止预估低估漏停。
- **[v0.5 2026-09-11]** 设计取舍：软限只降级（裁剪/换小模型，保住任务完成能力）、硬限才止损（宁可提前结束也不失控烧钱）；不做一刀切熔断，因为单轮超限多为历史堆积，裁剪即可恢复。顺带：Langfuse Generation 的 `model` 字段改记 `currentModel`，降级换模型后观测层与真实请求保持一致。
- **[ ] 演进方向**：按模型单价换算成本（¥）展示；预算参数透出 UI 可调。
