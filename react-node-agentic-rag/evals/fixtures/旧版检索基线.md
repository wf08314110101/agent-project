# 旧版检索基线系统说明（Python 单路 RAG）

## 系统定位

本系统是早期搭建的单路 RAG 基线，用于对照验证 Agentic RAG 的收益。前端同样通过 SSE 流式输出，后端为 Python FastAPI，检索只有稠密向量一路：查询文本经 bge 模型编码为 512 维语义向量后做余弦相似度检索，不包含稀疏关键词路，也没有服务端融合。

## 检索重试策略

基线系统也实现了查询改写重试：评估器判断资料不足时改写查询重新检索，最多尝试 3 次，超过后带着现有资料生成回答。改写由同一个对话模型完成，没有独立提示词模板。

## 工具与编排

基线系统没有工具调用能力，也没有 Agent 循环，是一条固定的「检索 → 评估 → 生成」链路。相关性评估直接用对话模型逐条打分，无结构化输出约束，也没有评估结果缓存，同一问题重复提问会重复评估。

## 已知问题

纯稠密检索对关键词与专名查询召回偏弱；无缓存导致重复提问成本翻倍；无工具导致无法回答计算类问题。这三点是 Agentic RAG 立项时要解决的核心差距。
