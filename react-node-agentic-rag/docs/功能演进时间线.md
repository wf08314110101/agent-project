## 1. 文档摄取管线

对应代码：[src/rag/](../backend/src/rag/)

- **[M1]** 同步管线：上传 → multipart 读 buffer → parser（md/txt/pdf/docx/csv/json/html）→ chunker（按标题分层 + 滑窗，块带 `title` 元数据）→ 本地嵌入 → Qdrant upsert。一次请求内串行完成。
- **[M1]** 设计取舍：嵌入用 `@xenova/transformers` 跑本地 ONNX（bge-small-zh-v1.5，512 维）而非 API——零成本、无网络依赖；代价是首启需下载模型（走 `HF_ENDPOINT=hf-mirror.com` 镜像）。
- **[M1]** 幂等去重：内容 SHA256 唯一索引，同文件返回 `duplicated: true` 而非报错，语义上「重复上传是合法操作」。
- **[M3]** 异步队列化：上传只做校验/判重/落盘（`data/uploads/<uuid>.<ext>`）即返回 202，`createIngestWorker` 单并发消费 pending 文档，状态流转 `pending → processing → ready | failed(error)`；原件处理完即删。
- **[M3]** 设计取舍：不引入 Redis/BullMQ，SQLite `status` 字段即队列——单机学习项目，单并发反而避免嵌入模型 CPU 争抢；宕机重启时把 `processing` 重置回 `pending`（自恢复）。
- **[M3]** 摄取中禁止删除（409），防 worker 读写竞态；老库无 `error/path` 列时 `ALTER TABLE` 迁移（catch 重复列）。
- **[ ] 演进方向**：多并发 worker + 按文档粒度进度百分比；PDF 扫描件 OCR；Qdrant payload 索引加速按 docId 删除。

## 2. 检索与相关性评估（search_kb 子图）

对应代码：[src/agent/search-graph.js](../backend/src/agent/search-graph.js)

- **[M1]** 单路检索：`query()` 向量相似 + `RETRIEVE_MIN_SCORE` 过滤，topK 可调。
- **[M2]** 升级为 LangGraph 子图（CRAG 模式）：`retrieve → grade → (rewrite → retrieve)*`——多查询并发检索、同块保留最高分合并去重，LLM 逐条判相关性并判断「材料是否足够」，不足时改写查询重试（`SEARCH_MAX_ATTEMPTS` 上限，默认 2）。
- **[M2]** 设计取舍：首轮不调用改写 LLM（原问题直查），只在评估不通过后才花改写的 token——大多数问题一轮就够，改写是兜底而非必经。
- **[M2]** 设计取舍：评估 JSON 解析失败时兜底「全部保留」，宁多勿漏——评估器挂了不应阻断问答主链路。
- **[M4 2026-09-15]** 结构化输出从「提示词恳求 + json_object」升级为强制化：DeepSeek 不支持 `response_format: json_schema`（实测 400），改用 **tool-call 强制**（把返回值定义成 function、`tool_choice` 钉死必须调用，服务端约束形状）+ 客户端 `validateSchema` 校验 + 校验失败回喂自纠一轮（[chatStructured](../backend/src/llm.js)）；返回 schema（GRADE_SCHEMA/REWRITE_SCHEMA）收敛到 prompts.js 作为单一事实源。取舍：tool-call 在 OpenAI 兼容 API 上支持面最广，强制力介于 json_object 与 json_schema 之间；「更强制 ≠ 零失败」，客户端校验永远是最后防线。
- **[ ] 演进方向**：混合检索（BM25 + 向量 RRF 融合）；Qdrant 服务端 `rerank`；评估结果缓存。

## 3. Agent 主图（ReAct loop）

对应代码：[src/agent/graph.js](../backend/src/agent/graph.js)

- **[M2]** LangGraph.js `StateGraph`：`agent`（流式 LLM + 工具绑定）→ 有 `tool_calls` 走 `tools`（执行 + `{role:'tool', tool_call_id}` 回填）→ 回 `agent`；无则 END。超 `AGENT_MAX_ITERATIONS` 轮注入 `FORCE_ANSWER` 并 `tool_choice:'none'` 强制直答。
- **[M2]** 设计取舍：LangGraph 只做编排/状态/reducer，LLM 调用仍走自封装 openai client——流式 token、usage、AbortSignal 全在掌控，不被框架抽象挡住；`emit/trace/signal/topK` 经 `configurable` 贯穿主图与子图。
- **[M2]** 设计取舍：正文 token 无论「思考还是答案」统一走 `delta` 事件——流式中无法预知本轮是否带 tool_calls，事后分叉会破坏流式体验；Action/Observation 由 `step` 事件承载，前端时间线呈现。
- **[M2]** 工具三件套：`search_knowledge`（invoke 子图 + 发 `sources` 事件）、`calculator`（正则白名单 + Function 求值）、`get_current_time`；幻觉工具名不抛错，返回「未知工具 + 可用工具列表」引导模型自纠。
- **[M4 2026-09-15]** 工具参数校验门：`toolsNode` 在执行前用 `validateToolArgs`（schema 复用 toolDefs，校验器收敛到共享的 [schema.js](../backend/src/schema.js)）校验 LLM 输出参数——失败转「参数校验失败: …」Observation 回喂自纠、不执行，避免坏参数静默变成空检索烧一轮。理由：LLM 输出是不可信输入，schema 只是「建议」不是保证。
- **[ ] 演进方向**：重复 Action 检测（连续同参调用提前终止）；多工具并行执行；Thought 阶段单独流式通道。

## 4. 对话与会话持久化

对应代码：[src/routes/chat.js](../backend/src/routes/chat.js)、[src/routes/sessions.js](../backend/src/routes/sessions.js)

- **[M1]** SSE 事件协议：`sources → delta* → usage → done | error`；`reply.raw.on('close')` + `writableEnded` 守卫区分「真断开」与「请求体读完的正常 close」，真断开才 abort LLM 流。
- **[M2]** 会话化：`sessions` + `chat_messages` 表（meta 存 sources/steps/usage，刷新页面可回放步骤）；无 sessionId 时以首问截断建会话；历史回放仅取 user/assistant 文本、窗口最近 20 条。
- **[M2]** 事件协议扩展：`step`(action/observation) 事件先行于正文，前端时间线折叠展示每次检索/评估。
- **[M4 2026-09-15]** **混合检索（稠密+稀疏 RRF）**：每个 point 双向量——`dense`（bge 稠密语义，Cosine）+ `sparse`（jieba 分词词频，Qdrant `modifier:'idf'` 服务端 BM25 加权），查询 `prefetch` 双路 → 服务端 `fusion:'rrf'` 一次往返融合（[qdrant.js](../backend/src/rag/qdrant.js)）。分词 [tokenizer.js](../backend/src/rag/tokenizer.js)：`@node-rs/jieba`（必须 `Jieba.withDict` 显式加载词典，否则全切单字）+ 停用词表；词表用 FNV-1a hash 直映射词 id，摄取/查询两端一致且零持久化。阈值语义迁移：`RETRIEVE_MIN_SCORE` 只作用于稠密路 prefetch（服务端 threshold），RRF 融合分是排名分不再二次过滤；稀疏路故障自动退化纯稠密（span 标记 `retrieval.mode`）。集合 schema 变更需删除重建，旧文档向量丢失要重新上传（一次性迁移成本）。**连带修复老缺陷**：sources 原来只取最后一轮检索命中，模型多轮搜索时前轮已评估通过的资料被清空——改为跨轮合并去重（[chat.js](../backend/src/routes/chat.js)），该缺陷此前被纯向量检索的低召回掩盖。实测：关键词/专名查询（CRAG、轮数）靠稀疏路把正确块顶到 rank1；回归补「关键词字面命中」用例后 6/6 通过。
- **[M4 2026-09-15]** **重复 Action 检测**：toolsNode 维护本次 invoke 的调用缓存（key = 工具名 + 递归排序键序的参数 hash，`{a,b}`/`{b,a}` 视为同参），命中则跳过执行直接复用上次 Observation，并追加「请勿重复调用」的系统提示引导模型换问法或直接作答（[graph.js](../backend/src/agent/graph.js)）。成功/失败结果都入缓存——同参重试注定同结果，失败应换问法而非原样重试。缓存挂在 `configurable.actionLog`（每次 invoke 独立 Map，跨请求/跨会话不共享）。取舍：不做「模糊相似」检测（只拦完全同参），避免误伤合法的换参重试。实测：强制模型同参重复调用 calculator，第二次零执行直接复用且模型读懂提示；回归 6/6 无误伤。
- **[M4 2026-09-15]** **长会话记忆压缩**：硬截 20 条改为「断点回放 + 滚动摘要」——定位模型：`summarized_seq` 为已压缩最大 seq（断点），上下文回放 `seq > 断点` 的全部消息（= 固定窗口 + 未压缩真空区，**零丢失**，上界 window+9 条），压缩对象为断点→窗口起点之间的消息，攒够 10 条触发一次增量 LLM 压缩（[agent/memory.js](../backend/src/agent/memory.js)）。**seq 水位断点而非数量断点**：seq 单调不回移，未来加删消息功能不会错位（数量断点在删除场景会 skip/重压）。取舍：纯文本摘要不走 chatStructured；压缩失败退化为仅回放窗口；攒批摊薄成本。实测：58 条会话从压缩记忆正确召回首对消息事实；新增 12 条触发合法再压缩；删已压缩区/回放区各 1 条后断点稳定、答问不受影响。

## 5. 可观测性（Langfuse + Phoenix）

对应代码：[src/obs/otel.js](../backend/src/obs/otel.js)（M4 起统一；此前为 langfuse.js + phoenix.js 双文件，已删）

- **[M1]** Langfuse 全链路：trace（问答）→ span（工具）+ generation（每轮/评估/改写），usage 换算注入；未配置时返回空壳对象，业务代码零判空；`flushAt: 1` 请求级 flush。
- **[M2]** Phoenix OTel 通道：`PHOENIX_ENABLED` 开关，手动打 OpenInference 规范 span（`openinference.span.kind`: LLM/TOOL/RETRIEVER），OTLP → `phoenix:6006/v1/traces`。
- **[M4 2026-09-15]** **可观测统一**：双份埋点（Langfuse SDK + 手动 OTel span）收敛为单一 OTel 管道（[obs/otel.js](../backend/src/obs/otel.js)）——NodeSDK `spanProcessors` 挂两个 BatchSpanProcessor 扇出（Phoenix + Langfuse OTLP `/api/public/otel/v1/traces` Basic Auth），删除 `langfuse` 依赖。关键实现：`rootSpan` 捕获根上下文 + `runInCtx`（context.with / AsyncLocalStorage）让子 span 自动挂树；Langfuse 侧属性映射：`openinference.span.kind`→观测类型、`llm.token_count.*`→usage、`langfuse.trace.name`/`langfuse.session.id`→trace 命名与会话分组。踩坑：子 span 不在根上下文内创建时各自成 trace、sessionId 丢失（OTel 默认无父级 → 新 traceId）。取舍：一次埋点双后端同构可见，代价是富数据（usage/level）改走属性约定而非 SDK 类型化 API。
- **[M2]** 踩坑：otel v2 移除 `Resource` 类，改用 `resourceFromAttributes()`。
- **[ ] 演进方向**：Langfuse 评分（评估器置信度回填）；Phoenix 自动 instrumentation 替代手动 span。

## 6. 生产化防线

对应代码：[src/server.js](../backend/src/server.js)、[scripts/regression.mjs](../scripts/regression.mjs)、[docker-compose.yml](../docker-compose.yml)

- **[M3]** 限流：@fastify/rate-limit 全局 120/min，chat 路由单独 20/min（route config 覆盖）。
- **[M3]** 降级直答：知识库为空时 `countPoints()` 预判，注入系统提示跳过检索轮直答并注明；有库无资料时由提示词约束「先说知识库未找到，再补充通用知识并注明」。Qdrant 抖动时预判失败不阻塞对话。
- **[M3]** 坏用例回归：`node scripts/regression.mjs` 自举 fixture → 5 类断言（KB 命中/改写检索/工具调用/不编造引用/幻觉探针），失败退出码 1，可挂 CI。
- **[M3]** 容器化：backend（node:24-slim + 构建工具）与 frontend（多阶段构建 + nginx）镜像入 compose，与 qdrant/phoenix 同栈；nginx 反代 `/api` 必须 `proxy_buffering off` 否则 SSE 被缓冲成一次性输出。
- **[M3]** 踩坑：node:24-slim 中 better-sqlite3 无预编译包回退 node-gyp，需 `python3 make g++`；compose 内 `environment` 覆盖 `QDRANT_URL=http://qdrant:6333`（.env 里的 localhost 只用于本机开发）。
- **[ ] 演进方向**：Qdrant 健康检查 + backend `depends_on: condition: service_healthy`；镜像 CI 构建；鉴权（API key / 用户体系）。
