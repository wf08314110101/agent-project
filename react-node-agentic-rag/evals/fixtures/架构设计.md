# Agentic RAG 系统架构说明

## 总体架构

本系统是生产形态的 Agentic RAG 参考实现，前端 React 通过 SSE 流式协议与 Fastify 后端通信。后端核心是 LangGraph 编排的主图，采用 ReAct 循环模式：agent 节点流式调用 LLM 并绑定工具，产生工具调用则进入 tools 节点执行，观察结果回填后继续下一轮，直到模型给出最终答案。

## search_kb 子图与 CRAG 模式

检索能力封装为 search_kb 子图，实现 CRAG（Corrective RAG）模式：retrieve 节点先执行混合检索，grade 节点用 LLM 逐条评估资料相关性并判断材料是否足够，不足时进入 rewrite 节点改写查询后重新检索，最多尝试 2 次。首轮不调用改写模型，原问题直查，只有评估不通过才花费改写的 token。

## 混合检索原理

检索采用稠密加稀疏的双路混合方案：稠密路是 bge 模型的 512 维语义向量做余弦相似度，稀疏路是 jieba 分词后的词频向量，由 Qdrant 服务端做 IDF 加权模拟 BM25。两路结果通过 RRF（倒数排名融合）在服务端一次往返合并，兼顾语义泛化与关键词字面命中。RRF 的基本原理是把每路的排名取倒数再求和，排名越靠前贡献越大，从而避免两路分数直接比较的量纲问题。

## 评估缓存

相关性评估结果做了内容寻址缓存：键为问题与命中块文本哈希的组合，同一问题再次提问时直接回放缓存的评估结论，跳过 LLM 评估调用。缓存按文本哈希编址，增删文档不会产生脏读。

## 工具体系

Agent 内置三类工具：search_knowledge 知识库检索、calculator 四则计算器（正则白名单校验表达式）、get_current_time 当前时间查询。工具参数在执行前经过 schema 校验门，重复的同参数调用会被检测并复用上次结果。
